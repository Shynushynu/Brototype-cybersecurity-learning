## 👤 a. User Accounts

A **user account** represents a person or process that can interact with a Linux system.

### 🔧 Important Commands

| Command            | Purpose                                  |
| ------------------ | ---------------------------------------- |
| `whoami`           | Shows the current username               |
| `id`               | Shows user ID, group ID, and groups      |
| `who`              | Shows currently logged-in users          |
| `w`                | Shows logged-in users and their activity |
| `adduser username` | Creates a new user                       |
| `passwd username`  | Sets or changes a user's password        |
| `usermod`          | Modifies a user account                  |
| `userdel username` | Deletes a user                           |

### 💻 Example

```bash
sudo adduser john
```

This creates a user named `john`.

## 👥 b. Groups

A **group** is a collection of users. Groups make it easier to manage permissions for multiple users.

### 🔧 Important Commands

| Command                      | Purpose                          |
| ---------------------------- | -------------------------------- |
| `groups`                     | Shows groups of the current user |
| `id username`                | Shows a user's groups            |
| `groupadd groupname`         | Creates a group                  |
| `groupdel groupname`         | Deletes a group                  |
| `usermod -aG group username` | Adds a user to a group           |
| `gpasswd -d username group`  | Removes a user from a group      |

### 💻 Example

```bash
sudo groupadd developers
sudo usermod -aG developers john
```

Now `john` belongs to the `developers` group.

> ⚠️ **Important:
> -a → Append/add without removing existing groups.
>-G → Specify the supplementary group(s) to add the user to.
>-aG means add the user to a supplementary group without removing their existing groups.

## 📁 c. File Permissions

Linux uses permissions to control what users can do with files and directories.

### 🔑 Basic Permissions

| Permission | Symbol | Meaning                           |
| ---------- | ------ | --------------------------------- |
| Read       | `r`    | View/read the file                |
| Write      | `w`    | Modify the file                   |
| Execute    | `x`    | Run the file / access a directory |

### 👤 Permission Categories

* **User (`u`)** → Owner of the file
* **Group (`g`)** → Users belonging to the file's group
* **Others (`o`)** → Everyone else

### 📄 Example

```text
-rwxr-xr--
```

Breakdown:

```text
-   rwx   r-x   r--
    │     │     │
   User  Group Others
```

* **User** → `rwx` → Read, Write, Execute
* **Group** → `r-x` → Read, Execute
* **Others** → `r--` → Read only

### 🔧 Changing Permissions with `chmod`

Add execute permission for the owner:

```bash
chmod u+x script.sh
```

Add write permission for the group:

```bash
chmod g+w file.txt
```

### 🔢 Numeric Permissions

| Number | Permission    |
| -----: | ------------- |
|    `4` | Read          |
|    `2` | Write         |
|    `1` | Execute       |
|    `0` | No permission |

For example:

```bash
chmod 755 script.sh
```

Means:

```text
Owner  → 7 = rwx
Group  → 5 = r-x
Others → 5 = r-x
```

### 🧮 How `755` Is Calculated

```text
7 = 4 + 2 + 1 = rwx
5 = 4 + 0 + 1 = r-x
5 = 4 + 0 + 1 = r-x
```

## 👑 d. Ownership

Every Linux file has an **owner** and an associated **group**.

You can view them using:

```bash
ls -l
```

### 📄 Example

```text
-rw-r--r-- 1 john developers 1200 file.txt
```

Here:

* `john` → File owner
* `developers` → File group

### 🔄 Change Owner

Use `chown`:

```bash
sudo chown alice file.txt
```

### 👤 Change Owner and Group

```bash
sudo chown alice:developers file.txt
```

### 👥 Change Group Only

Use `chgrp`:

```bash
sudo chgrp developers file.txt
```

## 🛡️ e. Privilege Management

**Privilege management** controls what actions a user is allowed to perform on the system.

Linux normally separates **regular users** from users with **administrative privileges**.

### 🔑 `sudo`

`sudo` allows an authorized user to run a command with elevated privileges.

Example:

```bash
sudo apt update
```

The command runs with administrative privileges.

### 👑 Check the Current User

```bash
whoami
```

If the output is:

```text
root
```

you are using the `root` account.

### 🔄 `su`

`su` can switch to another user account.

```bash
su username
```

### 🛡️ Why Privilege Management Matters

Privilege management follows the **Principle of Least Privilege (PoLP)**:

> Give users only the permissions they need to perform their tasks.

This helps reduce the impact of mistakes, unauthorized access, and compromised accounts.

## 🎯 Key Takeaways

* 👤 **Users** represent accounts on a Linux system.
* 👥 **Groups** allow permissions to be managed for multiple users.
* 🔐 **Permissions** control who can read, write, or execute files.
* 👑 **Ownership** identifies the owner and group associated with a file.
* 🛡️ **Privileges** control access to administrative operations.
* ⚡ `chmod` changes permissions.
* 🔄 `chown` changes ownership.
* 👥 `usermod -aG` adds a user to a supplementary group.
* 🔑 `sudo` allows authorized users to execute commands with elevated privileges.
* 🛡️ The **Principle of Least Privilege** improves system security.
