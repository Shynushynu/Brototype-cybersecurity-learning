# 🛠️ Apply Through Hands-on Tasks

## a. Analyze Malware Samples Safely 🦠

- Use a **Virtual Machine (VM)** for malware analysis.
- Take a **snapshot** before testing.
- Use safe test files such as the **EICAR test file**.
- Observe processes, files, and network activity.
- Record your observations.

**Goal:** Understand how malware behaves without affecting your real computer.

---

## b. Research Recent CVEs 🔍

- Find a recent **CVE (Common Vulnerabilities and Exposures)**.
- Identify the affected software and versions.
- Understand the vulnerability.
- Check its **CVSS severity score**.
- Research the impact.
- Find the official vendor advisory.
- Identify available patches or mitigations.

**Goal:** Learn how security professionals research and assess vulnerabilities.

---

## c. Perform OSINT Investigations 🌐

**OSINT (Open-Source Intelligence)** means collecting information from publicly available sources.

### Practice:

- Search public websites.
- Examine domain information.
- Review public DNS information.
- Identify technologies used by websites.
- Collect information from public documents.
- Verify information using multiple sources.

**Goal:** Learn how to gather useful intelligence safely and legally.

---

## d. Document Attack Techniques 📝

For each attack technique, document:

| Section | Example |
|---|---|
| **Technique** | Phishing |
| **Description** | Deceptive messages designed to trick users |
| **Attack Vector** | Email / Message |
| **Indicators** | Suspicious links, fake domains |
| **Impact** | Credential theft |
| **Detection** | Email filtering, monitoring |
| **Prevention** | MFA, security awareness |

**Goal:** Learn to clearly document how attacks work and how to defend against them.

---

## e. Create Vulnerability Reports 🛡️

A basic vulnerability report should contain:

1. **Title**
2. **Vulnerability Description**
3. **Affected System**
4. **Severity**
5. **Technical Details**
6. **Evidence**
7. **Reproduction Steps**
8. **Impact**
9. **Remediation**
10. **References**

### Example

> **Title:** Missing Security Header  
> **Severity:** Low  
> **Impact:** May increase exposure to certain web-based attacks.  
> **Recommendation:** Configure appropriate security headers based on the application's requirements.

---

> ⚠️ **Safety:** Only test systems, applications, domains, and samples that you own or have explicit permission to analyze.
