## 1. Error Handling

Error handling means detecting and managing errors that occur while a program runs.

### 💻 Example

```python
num = int(input("Enter a number: "))
print(num)
```

If the user enters `hello`, Python raises a `ValueError`.

We can handle this error using `try-except`.

---

## 2. Try-Except Blocks

Try-except blocks allow us to handle errors and prevent unexpected program termination.

### 🔑 Important Keywords

| Keyword | Purpose |
|---|---|
| `try` | Contains code that might cause an error |
| `except` | Handles a matching exception |
| `else` | Runs if no exception occurs in the `try` block |
| `finally` | Runs whether an exception occurs or not |

### 💻 Example

```python
try:
    num = int(input("Enter a number: "))
    print(10 / num)

except ValueError:
    print("Please enter a valid number.")

except ZeroDivisionError:
    print("Cannot divide by zero.")

else:
    print("Program executed successfully.")

finally:
    print("Program finished.")
```

### 📝 Explanation

- If the user enters text instead of a number, `ValueError` is handled.
- If the user enters `0`, `ZeroDivisionError` is handled.
- If no error occurs, the `else` block runs.
- The `finally` block runs in all these cases.

## 3. Debugging

Debugging means **finding and fixing errors in your code**.

### 🔍 Types of Errors

| Error Type | Meaning | Example |
|---|---|---|
| Syntax Error | Incorrect Python syntax | Missing `:` after an `if` statement |
| Runtime Error | Error during program execution | `10 / 0` |
| Logical Error | Program runs but produces an incorrect result | Using `+` instead of `*` |

### 💻 Example

```python
x = 10
y = 0

print("x =", x)
print("y =", y)

result = x / y
```

### 📝 Explanation

The program raises a `ZeroDivisionError` because division by zero is not allowed.

The `print()` statements help us inspect variable values before the error occurs.

### 🛠️ Debugging Tools

- `print()` statements
- VS Code debugger
- Breakpoints
- Python traceback messages

## 4. Logging Errors

Logging records information about what happens while a program runs, including errors.

Python provides a built-in `logging` module, so you do not need to install an additional library.

### 💻 Example

```python
import logging

logging.basicConfig(
    filename="app.log",
    level=logging.ERROR
)

try:
    result = 10 / 0

except ZeroDivisionError:
    logging.exception("An error occurred")
```

### 📝 Explanation

- `import logging` imports the logging module.
- `filename="app.log"` stores log messages in a file.
- `level=logging.ERROR` records error-level messages and more severe messages.
- `logging.exception()` records the error message and traceback inside an `except` block.

### 📊 Logging Levels

| Level | Purpose |
|---|---|
| `DEBUG` | Detailed information for debugging |
| `INFO` | General program information |
| `WARNING` | Something unexpected happened |
| `ERROR` | An operation failed |
| `CRITICAL` | A serious failure occurred |

### 🔐 Cybersecurity Use Case

Logging is useful for recording application errors, investigating failures, and troubleshooting security tools.

## 5. Building Reliable Scripts

A reliable script handles expected errors, validates input, and avoids crashing unnecessarily.

### 💻 Example: Handling File Errors

```python
try:
    with open("data.txt", "r") as file:
        content = file.read()
        print(content)

except FileNotFoundError:
    print("The file does not exist.")

except PermissionError:
    print("You do not have permission to read this file.")
```

### 📝 Explanation

- `with open()` opens the file and manages its closure.
- `FileNotFoundError` handles a missing file.
- `PermissionError` handles insufficient file permissions.

Instead of allowing these errors to remain unhandled, the program displays a useful message.

### ✅ Best Practices

- Catch specific exceptions instead of using a bare `except`.
- Validate user input.
- Use `with open()` for file handling.
- Log errors when you need to investigate them.
- Avoid silently ignoring errors.
- Test your code with invalid inputs and missing files.
- Do not expose passwords, tokens, or other sensitive information in logs.
