## 🔐 1. Introduction to Digital Signatures

A **Digital Signature** is a cryptographic technique used to verify the authenticity and integrity of digital messages, documents, or files.

It uses **asymmetric cryptography**, involving two keys:

- 🔑 **Private Key:** Used to create the digital signature.
- 🔓 **Public Key:** Used to verify the digital signature.

A digital signature helps establish:

- **Authenticity:** Confirms who signed the data, provided the public key is reliably associated with that identity.
- **Integrity:** Detects whether the data was modified after signing.
- **Non-Repudiation:** Provides evidence that the holder of the private key signed the data, subject to proper key control and other conditions.

## 🪪 2. Identity Verification

Identity verification ensures that a digital signature belongs to the claimed sender.

### How it works

1. The sender creates a digital signature using their private key.
2. The receiver obtains the sender's public key.
3. The receiver verifies the signature using that public key.
4. If verification succeeds, the signature is mathematically valid for that data and key.

**Important:** A public key alone does not reveal the real-world identity of its owner. A trusted certificate or another reliable identity-verification mechanism is needed to establish that connection.

## ⚖️ 3. Non-Repudiation

**Non-repudiation** means providing evidence that makes it difficult for a signer to deny having signed a particular document or message.

### How it works

- The signer uses their private key to sign the data.
- The receiver verifies the signature using the corresponding public key.
- The valid signature provides evidence of the signing operation.

### Example

Alice digitally signs a contract using her private key.

Bob verifies the signature using Alice's trusted public key.

This provides evidence that the contract was signed using the private key associated with Alice.

**Note:** Non-repudiation depends on proper private-key protection, identity verification, and applicable legal and technical requirements.

## 🔄 4. Signature Workflow

A digital signature generally follows these steps:

1. **Data Creation:** The sender creates a message or document.
2. **Hashing:** A cryptographic hash function (such as SHA-256) generates a hash of the data.
3. **Signing:** The sender signs the hash using their private key.
4. **Transmission:** The sender sends the original data and digital signature to the receiver.
5. **Verification:** The receiver checks the signature using the sender's public key and compares the resulting hash with a newly calculated hash.

## 🔍 5. Verification Process

The verification process checks whether the digital signature is valid for the received data.

### Verification steps

1. The receiver receives the original data and digital signature.
2. The receiver calculates a new hash of the received data.
3. The receiver uses the sender's public key to verify the digital signature.
4. The signature scheme validates the signed hash or message.
5. If verification succeeds, the signature is valid for the received data.

### Possible Results

| Result | Meaning |
|---|---|
| Valid | Signature matches the received data and public key. |
| Invalid | Signature verification fails. |
| Modified Data | Changes to the signed data cause verification to fail. |
| Wrong Public Key | Verification generally fails when an unrelated key is used. |

**Remember:** A valid signature does not automatically prove that the signer is trustworthy. The identity associated with the public key must also be verified.

## 🏛️ 6. Trust Models

A trust model defines how users establish confidence in the identity associated with a public key.

### 1. Public Key Infrastructure (PKI)

PKI is a system that manages digital certificates and public-key trust.

It commonly involves:

- **Certificate Authority (CA):** Issues and signs digital certificates.
- **Digital Certificate:** Connects an identity with a public key.
- **Registration Authority (RA):** Helps verify certificate applicants.
- **Certificate Revocation:** Allows certificates to be invalidated when necessary.

### 2. Web of Trust

A decentralized trust model in which users establish trust through other users' key signatures.

It is commonly associated with OpenPGP.

### 3. Direct Trust

A user obtains a public key directly from its owner and independently verifies its authenticity through a trusted channel.

### PKI Workflow

```text
       User Identity
             |
      Identity Verification
             |
      Certificate Authority
             |
      Digital Certificate
             |
      Public Key Association
             |
       Certificate Validation
             |
        Established Trust
```

## 🔐 7. Digital Signature vs Encryption

| Feature | Digital Signature | Encryption |
|---|---|---|
| Main Purpose | Authenticity and integrity | Confidentiality |
| Sender's Key | Private key | Public key (in typical public-key encryption) |
| Receiver's Key | Public key for verification | Private key |
| Protects | Authenticity and integrity | Data confidentiality |
| Reversible? | No decryption process | Yes, using the appropriate decryption key |

**Important:** Digital signatures and encryption solve different security problems. They can be combined to provide authenticity, integrity, and confidentiality.

## 🌍 8. Real-World Applications

- 📄 Digitally signing PDF documents.
- 💳 Secure financial transactions.
- 🌐 SSL/TLS certificate authentication.
- 💻 Software and application code signing.
- 🏢 Electronic contracts and agreements.
- 📦 Verifying software updates and downloaded files.

## 🎯 9. Key Takeaways

- Digital signatures use asymmetric cryptography.
- The private key creates the signature.
- The public key verifies the signature.
- Hashing helps detect changes in signed data.
- Non-repudiation provides evidence of signing.
- PKI establishes trust between identities and public keys.
- Digital signatures provide authenticity and integrity, not confidentiality.

**Remember:** A digital signature is like a cryptographic seal that helps prove who signed the data and whether it has been modified.
