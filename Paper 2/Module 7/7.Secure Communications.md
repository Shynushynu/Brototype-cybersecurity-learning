## 1. HTTPS

### 🔹 What is HTTPS?

**HTTPS (Hypertext Transfer Protocol Secure)** is the secure version of HTTP. It protects communication between a web browser (client) and a web server using TLS encryption.

### 🔹 How HTTPS Works

1. The browser connects to the web server.
2. The server provides its digital certificate.
3. The browser verifies the server's certificate.
4. The client and server establish secure session keys through the TLS handshake.
5. Data is encrypted and exchanged securely.

### 🔹 Security Provided by HTTPS

| Security Goal | Description |
|---|---|
| Confidentiality | Prevents unauthorized people from reading transmitted data. |
| Integrity | Detects unauthorized modification of transmitted data. |
| Authentication | Helps verify the identity of the server. |

### 🔹 Example

When you visit `https://www.google.com`, HTTPS protects the communication between your browser and Google's server.

## 2. TLS (Transport Layer Security)

### 🔹 What is TLS?

**TLS (Transport Layer Security)** is a cryptographic protocol that provides secure communication over a network.

It protects data exchanged between two communicating systems.

### 🔹 Main Functions of TLS

1. Encryption – Protects data from being read by unauthorized parties.
2. Authentication – Verifies the identity of communicating parties when configured.
3. Integrity – Detects unauthorized modifications to transmitted data.

### 🔹 TLS Handshake

The TLS handshake establishes the security parameters and shared session keys before protected application data is exchanged.

**Basic TLS 1.3 handshake:**

1. Client Hello – The client sends supported TLS versions, cipher suites and key-share information.
2. Server Hello – The server selects the security parameters and responds with its key-share information.
3. Key Establishment – Both sides derive shared session keys.
4. Authentication – The server provides its certificate and proves its identity.
5. Finished Messages – Both sides verify the handshake.
6. Secure Communication – Encrypted application data is exchanged.

### 🔹 Important TLS Concepts

| Concept | Description |
|---|---|
| Cipher Suite | Defines the cryptographic algorithms used for communication. |
| Session Keys | Temporary symmetric keys used to encrypt communication. |
| Key Exchange | Establishes shared secrets between communicating parties. |
| Certificate | Helps authenticate the server's identity. |

## 3. SSL History

### 🔹 What is SSL?

**SSL (Secure Sockets Layer)** was an earlier cryptographic protocol developed to secure communication over networks.

It was the predecessor of TLS.

### 🔹 Evolution of SSL and TLS

| Version | Year | Status |
|---|---:|---|
| SSL 1.0 | Never publicly released | Unreleased |
| SSL 2.0 | 1995 | Deprecated |
| SSL 3.0 | 1996 | Deprecated |
| TLS 1.0 | 1999 | Deprecated |
| TLS 1.1 | 2006 | Deprecated |
| TLS 1.2 | 2008 | Widely supported |
| TLS 1.3 | 2018 | Modern recommended version |

### 🔹 SSL vs TLS

| SSL | TLS |
|---|---|
| Older security protocol | Modern successor to SSL |
| Contains known security weaknesses | Provides stronger security |
| No longer considered secure | TLS 1.2 and 1.3 are commonly used |
| Deprecated | Preferred for secure communication |

> ⚠️ **Important:** SSL is obsolete and should not be used. Modern secure communication should use TLS 1.2 or TLS 1.3.

## 4. Secure Channels

### 🔹 What is a Secure Channel?

A **secure channel** is a protected communication path between two systems that helps prevent unauthorized access, data modification and impersonation.

### 🔹 Security Properties

1. Confidentiality – Protects information from unauthorized reading.
2. Integrity – Ensures transmitted data has not been modified.
3. Authentication – Verifies the identity of communicating parties.
4. Forward Secrecy – Helps ensure that compromising long-term private keys does not expose previously established session keys.

### 🔹 Examples of Secure Channels

| Technology | Purpose |
|---|---|
| HTTPS | Secures web communication using TLS. |
| SSH | Provides secure remote access and communication. |
| VPN | Creates an encrypted connection across an untrusted network. |
| TLS | Protects application communication between systems. |

### 🔹 Example

When you log in to a website using HTTPS, TLS establishes a secure channel between your browser and the website's server.

## 5. Certificate Concepts

### 🔹 What is a Digital Certificate?

A **digital certificate** is an electronic document that connects an identity (such as a website's domain name) with a public key.

It is digitally signed by a Certificate Authority (CA) or, in some cases, self-signed.

### 🔹 Important Certificate Components

| Component | Description |
|---|---|
| Subject | Identifies the certificate owner. |
| Public Key | Contains the owner's public key. |
| Issuer | Identifies who issued the certificate. |
| Validity Period | Specifies when the certificate is valid. |
| Serial Number | Uniquely identifies the certificate from its issuer. |
| Digital Signature | Allows verification that the certificate was signed by its issuer. |

### 🔹 What is a Certificate Authority (CA)?

A **Certificate Authority (CA)** is a trusted organization that issues and digitally signs certificates after performing the required validation.

Examples:
- Let's Encrypt
- DigiCert
- GlobalSign

### 🔹 Certificate Verification Process

1. The server sends its certificate to the browser.
2. The browser checks the certificate's validity period.
3. It verifies the certificate's digital signature and certificate chain.
4. It checks whether the certificate matches the requested domain.
5. It checks applicable revocation information and other validation requirements.
6. If verification succeeds, the browser can proceed with the secure connection.

### 🔹 What is PKI?

**PKI (Public Key Infrastructure)** is a framework of technologies, policies and trusted entities used to manage digital certificates and public-key cryptography.

Main components:

- Certificate Authority (CA)
- Registration Authority (RA)
- Digital Certificates
- Public and Private Keys
- Certificate Revocation Lists (CRL)
- Online Certificate Status Protocol (OCSP)

## 🎯 Key Takeaways

- HTTPS secures HTTP communication using TLS.
- TLS provides encryption, authentication and integrity.
- SSL is the predecessor of TLS and is obsolete.
- A secure channel protects communication between systems.
- Digital certificates connect identities with public keys.
- Certificate Authorities issue and sign digital certificates.
- PKI manages certificates and public-key trust.
