# 🔐 4. Understand Asymmetric Encryption

## 📌 Overview

**Asymmetric Cryptography** is a cryptographic technique that uses a pair of mathematically related keys:

- 🔓 **Public Key:** Can be shared openly with others.
- 🔒 **Private Key:** Must be kept secret by its owner.

Unlike symmetric encryption, which uses the same secret key for encryption and decryption, asymmetric cryptography uses different keys for different cryptographic operations.

It provides important security services such as confidentiality, authentication, and digital signatures.

## 1. 🔓 Public Keys

A **Public Key** is a cryptographic key that can be shared openly with other people or systems.

Its purpose depends on the cryptographic algorithm.

### Main Uses

- **Encryption:** Encrypts data in public-key encryption systems such as RSA.
- **Digital Signature Verification:** Verifies signatures created using the corresponding private key.
- **Key Agreement:** Participates in establishing a shared secret using algorithms such as ECDH.

### Example

Imagine Alice wants to receive an encrypted message from Bob.

1. Alice generates a public-private key pair.
2. Alice shares her public key with Bob.
3. Bob encrypts the message using Alice's public key.
4. Bob sends the encrypted message to Alice.
5. Alice decrypts it using her corresponding private key.

Only Alice possesses the private key needed to decrypt the message.

---

## 2. 🔒 Private Keys

A **Private Key** is a secret cryptographic key that must be protected by its owner.

It is mathematically related to its corresponding public key.

### Main Uses

- **Decryption:** Decrypts ciphertext in public-key encryption systems such as RSA.
- **Digital Signatures:** Creates digital signatures that can be verified using the corresponding public key.
- **Key Agreement:** Participates in generating a shared secret using algorithms such as Diffie-Hellman.

### Example

Continuing the previous example:

1. Alice receives Bob's encrypted message.
2. Alice uses her private key to decrypt it.
3. She obtains the original plaintext.

**Important:** A private key must never be shared. Anyone who obtains it may be able to impersonate its owner or access protected information.

## 3. 🔄 Key Exchange

**Key Exchange** is a cryptographic process that allows two parties to establish a shared secret over an insecure communication channel.

One popular key agreement algorithm is **Diffie-Hellman (DH)**.

### How Diffie-Hellman Works

Imagine Alice and Bob want to establish a shared secret without directly transmitting the secret over the network.

**Step 1:** Alice generates a private value (a), and Bob generates a private value (b).

**Step 2:** Both calculate their public values using their private values.

**Step 3:** Alice and Bob exchange their public values over the network.

**Step 4:** Alice combines Bob's public value with her private value.

**Step 5:** Bob combines Alice's public value with his private value.

**Step 6:** Both calculate the same shared secret.

<text weight="semibold" color="success">Result: Alice and Bob have the same shared secret.</text>

### Important Points

- DH is a key agreement algorithm, not an encryption algorithm.
- The shared secret is never directly transmitted.
- The shared secret can be used with a Key Derivation Function (KDF) to generate symmetric encryption keys.
- Authenticated DH helps prevent Man-in-the-Middle (MITM) attacks.

**Remember:**

- AES → Symmetric encryption.
- RSA → Public-key encryption and digital signatures.
- DH → Key agreement.
- ECDH → Elliptic Curve key agreement.

## 4. 🛡️ Digital Trust

**Digital Trust** means verifying that a public key actually belongs to the person, organization, or server claiming to own it.

If an attacker replaces a legitimate public key with their own, communication could be intercepted.

To establish trust, we use **Public Key Infrastructure (PKI)**.

### What is PKI?

PKI is a framework of technologies, policies, and processes used to manage public keys and digital certificates.

### Important Components

| Component | Purpose |
|---|---|
| Digital Certificate | Associates an identity with a public key |
| Certificate Authority (CA) | Issues and digitally signs certificates |
| Registration Authority (RA) | Helps verify certificate applicants |
| Public Key | Used for encryption, verification, or key agreement |
| Private Key | Used for decryption, signing, or key agreement |

### How Digital Certificates Work

1. A website generates a public-private key pair.
2. It requests a digital certificate from a Certificate Authority.
3. The CA verifies the website's identity according to its validation process.
4. The CA digitally signs the certificate.
5. The browser receives the certificate and validates its signature and trust chain.
6. If validation succeeds and other checks pass, the browser can trust the certificate's binding between the website identity and its public key.

### What is a Digital Signature?

A **Digital Signature** is a cryptographic mechanism used to verify the authenticity and integrity of digital data.

#### How It Works

**Sender:**

1. Creates a hash of the message.
2. Uses their private key to create a digital signature.
3. Sends the message and signature to the receiver.

**Receiver:**

1. Receives the message and signature.
2. Uses the sender's public key to verify the signature.
3. Checks whether the message is authentic and unchanged.

**Important:** Digital signatures provide authenticity and integrity, but they do not encrypt the message or provide confidentiality by themselves.

## 5. 🌐 Practical Applications

Asymmetric cryptography is widely used in cybersecurity and secure communication.

| Application | How It Is Used |
|---|---|
| HTTPS | Authenticates servers and helps establish secure connections |
| SSH | Uses public-key authentication |
| Digital Signatures | Verifies authenticity and integrity |
| Email Security | Protects email using systems such as PGP |
| Software Signing | Verifies software publisher identity and integrity |
| TLS | Uses public-key cryptography for authentication and key establishment |

### Real-World Example: HTTPS

When you visit an HTTPS website:

1. Your browser connects to the web server.
2. The server provides its digital certificate.
3. The browser validates the certificate.
4. The TLS handshake establishes shared symmetric traffic keys.
5. AES-GCM or ChaCha20-Poly1305 encrypts the actual communication.

**Important:** Modern HTTPS commonly uses ephemeral Diffie-Hellman key agreement (ECDHE) rather than RSA encryption to establish shared secrets.

Asymmetric cryptography helps establish trust and secure key establishment, while symmetric cryptography handles the actual data encryption.

## 6. 🔑 Popular Asymmetric Algorithms

| Algorithm | Purpose |
|---|---|
| RSA | Public-key encryption and digital signatures |
| ECC | Family of cryptographic techniques based on elliptic curves |
| Diffie-Hellman (DH) | Key agreement |
| ECDH | Elliptic Curve Diffie-Hellman key agreement |
| ECDSA | Elliptic Curve Digital Signature Algorithm |
| Ed25519 | Digital signature scheme based on Edwards-curve cryptography |

**Note:** ECC is a family of cryptographic techniques, while ECDH and ECDSA are specific algorithms within that family.

## 7. ⚖️ Symmetric vs Asymmetric Cryptography

| Feature | Symmetric | Asymmetric |
|---|---|---|
| Keys | One shared secret key | Public-private key pair |
| Speed | Generally faster | Generally slower |
| Key Distribution | Requires secure key establishment | Public key can be shared openly |
| Key Management | Shared secret must be protected | Private key must be protected |
| Main Uses | Bulk data encryption | Authentication, signatures, key agreement and encryption |
| Examples | AES, ChaCha20 | RSA, ECDH, ECDSA |

## 8. 👥 Real-World Example

Imagine Alice wants to send a confidential message to Bob using RSA public-key encryption.

### Step 1: Key Generation

Bob generates two mathematically related keys:

- Public Key
- Private Key

### Step 2: Public Key Sharing

Bob shares his public key with Alice.

### Step 3: Encryption

Alice encrypts her message using Bob's public key.

### Step 4: Transmission

Alice sends the encrypted message to Bob over the internet.

### Step 5: Decryption

Bob uses his private key to decrypt the message.

**Note:** This is a simplified conceptual example. In real applications, hybrid encryption is commonly used: public-key cryptography protects or establishes a symmetric key, and symmetric encryption protects the actual message.

## 9. 🎯 Key Takeaways

- Asymmetric cryptography uses mathematically related public and private keys.
- A public key can be shared openly.
- A private key must remain secret.
- RSA can provide public-key encryption and digital signatures.
- Digital signatures provide authenticity and integrity.
- Diffie-Hellman establishes a shared secret.
- A KDF can derive symmetric keys from shared secrets.
- PKI establishes trust between identities and public keys.
- Digital certificates connect identities with public keys.
- Modern HTTPS combines asymmetric and symmetric cryptography.
