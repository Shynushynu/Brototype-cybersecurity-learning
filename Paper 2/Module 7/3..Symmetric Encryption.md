## 1. Introduction to Symmetric Encryption

**Symmetric encryption** is a cryptographic technique that uses the same secret key for both encryption and decryption.

It converts readable information (plaintext) into unreadable information (ciphertext) using a secret key.

Only someone who possesses the correct secret key can decrypt the ciphertext.

### Example

Imagine Alice wants to send a confidential message to Bob.

- Alice encrypts the message using a secret key.
- Bob receives the encrypted message.
- Bob uses the same secret key to decrypt it.

**Main objective:** Confidentiality – preventing unauthorized people from reading sensitive information.

## 2. Shared-Key Encryption

Shared-key encryption is another name for symmetric encryption.

Both communicating parties must possess the same secret key.

### How it works

Let's consider:

- Alice = Sender
- Bob = Receiver
- K = Shared secret key
- M = Original message
- C = Encrypted message

**Encryption:**

$$C = E(K,M)$$

**Decryption:**

$$M = D(K,C)$$

Where:

- E = Encryption algorithm
- D = Decryption algorithm
- K = Secret key
- M = Plaintext
- C = Ciphertext

### Example workflow

1. Alice and Bob securely obtain the same secret key.
2. Alice encrypts her message using that key.
3. Alice sends the ciphertext to Bob.
4. Bob uses the same key to decrypt the message.
5. Bob gets the original plaintext.

**Advantages:**
- Fast encryption and decryption.
- Suitable for large amounts of data.
- Requires less computational power than many public-key encryption operations.

**Disadvantage:** The biggest challenge is securely sharing the secret key between communicating parties.

## 3. Encryption Workflows

An encryption workflow describes how plaintext is converted into ciphertext and how the receiver recovers the original information.

### Encryption process

1. **Plaintext:** Original readable information.
2. **Secret Key:** Key used to encrypt the information.
3. **Encryption Algorithm:** Performs mathematical operations on the plaintext.
4. **Ciphertext:** Encrypted unreadable information.
5. **Transmission:** Ciphertext is sent to the receiver.

### Decryption process

1. Receiver obtains the ciphertext.
2. Receiver has access to the same secret key.
3. Decryption algorithm processes the ciphertext.
4. Original plaintext is recovered.

### Important concepts

**IV (Initialization Vector)**
- An additional value used by certain encryption modes.
- Helps ensure that encrypting the same plaintext with the same key does not always produce the same ciphertext.
- It is generally not secret, but must follow the requirements of the encryption mode.

**Nonce (Number Used Once)**
- A value that should not be reused with the same key in modes such as AES-GCM.
- Helps maintain encryption security.

**Padding**
- Some encryption modes require data to be adjusted to a particular block size.
- Padding fills the remaining space when necessary.

## 4. Key Protection

The encryption key is the most important secret in symmetric encryption.

If an attacker obtains the secret key, they may be able to decrypt the protected information.

### Key protection techniques

| Technique | Purpose |
|---|---|
| Strong key generation | Creates unpredictable keys |
| Secure key storage | Prevents unauthorized access |
| Key rotation | Replaces keys periodically |
| Access control | Limits who can access keys |
| Key backup | Protects against accidental key loss |
| Secure key exchange | Protects keys during distribution |

### Key Generation

Keys should be generated using a cryptographically secure random number generator (CSPRNG).

For example, AES supports:
- AES-128 (128-bit key)
- AES-192 (192-bit key)
- AES-256 (256-bit key)

**Important:** Never use ordinary passwords directly as AES encryption keys. Use a suitable key derivation function (KDF) when deriving keys from passwords.

## 5. Practical Use Cases

Symmetric encryption is widely used in everyday technology.

| Use case | How it is used |
|---|---|
| HTTPS | TLS uses symmetric encryption to protect application data |
| File encryption | Protects confidential files |
| Disk encryption | Protects information stored on hard drives |
| Database encryption | Protects sensitive database information |
| VPN | Protects network traffic |
| Messaging applications | Protects message contents |

### Real-world example: HTTPS

When you visit a website using HTTPS:

1. Your browser and the server establish a secure TLS connection.
2. They negotiate encryption keys during the handshake.
3. Symmetric encryption protects the data exchanged.
4. The communication remains encrypted during transmission.

**Remember:** Asymmetric cryptography is commonly used during the handshake, while symmetric encryption handles the actual data transfer efficiently.

## 6. Security Considerations

Although symmetric encryption is fast and powerful, improper implementation can create security vulnerabilities.

### Important security considerations

**1. Key Leakage**

If the secret key is exposed, attackers may decrypt protected information.

**2. Weak Keys**

Predictable or poorly generated keys make encryption vulnerable to attacks.

**3. Key Reuse**

Reusing keys or nonces incorrectly can compromise security.

**4. Insecure Encryption Modes**

Some encryption modes, such as ECB, reveal patterns in encrypted data.

**5. Brute-Force Attacks**

Attackers may attempt different keys until they find the correct one. Strong keys make this computationally impractical.

**6. Lack of Authentication**

Encryption alone does not necessarily guarantee that the message has not been modified.

Use authenticated encryption, such as AES-GCM or ChaCha20-Poly1305, to provide confidentiality and integrity together.

## 7. Common Symmetric Encryption Algorithms

### 1. AES (Advanced Encryption Standard)

- Modern and widely used.
- Supports 128, 192 and 256-bit keys.
- Considered secure when implemented correctly.

### 2. DES (Data Encryption Standard)

- Uses a 56-bit effective key.
- No longer considered secure.
- Vulnerable to brute-force attacks.

### 3. 3DES (Triple DES)

- Applies DES operations three times.
- Developed to improve DES security.
- Deprecated for modern encryption.

### 4. ChaCha20

- Modern stream cipher.
- Efficient in software implementations.
- Commonly paired with Poly1305 for authentication.
