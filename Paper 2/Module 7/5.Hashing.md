## 🔹 1. Introduction to Hashing

**Hashing** is the process of converting input data of any size into a fixed-length value called a **hash value** or **message digest** using a mathematical algorithm called a hash function.

### Key Characteristics

- Converts data into a fixed-length output.
- The same input always produces the same hash.
- A small change in input produces a significantly different hash.
- Cryptographic hashing is designed to be computationally infeasible to reverse.
- It is generally a one-way process.

### Example

**Input:**
```text
Hello
```

**SHA-256 Hash:**
```text
185f8db32271fe25f561a6fc938b2e264306ec304eda518007d1764826381969
```

If we change the input:

```text
Hello!
```

The resulting hash will be completely different.

> **Important:** Hashing is not encryption. Encryption is reversible using the appropriate key, whereas cryptographic hashing is designed to be one-way.

## 🔹 2. Hash Functions

A **hash function** is a mathematical algorithm that takes input data and produces a fixed-length hash value.

### Common Hashing Algorithms

| Algorithm | Output Size | Security Status |
|---|---:|---|
| MD5 | 128 bits | Broken |
| SHA-1 | 160 bits | Broken for collision resistance |
| SHA-256 | 256 bits | Secure for general cryptographic hashing |
| SHA-384 | 384 bits | Secure |
| SHA-512 | 512 bits | Secure |
| SHA-3 | Variable | Secure |

### Important Properties of Cryptographic Hash Functions

1. **Deterministic:** Same input always produces the same output.
2. **Fixed-length output:** Output size remains fixed for a given algorithm.
3. **Preimage resistance:** Difficult to find the original input from its hash.
4. **Second-preimage resistance:** Difficult to find another input with the same hash as a given input.
5. **Collision resistance:** Difficult to find any two different inputs that produce the same hash.
6. **Avalanche effect:** A small input change causes a significant change in the output.

### Python Example

```python
import hashlib

data = "Hello World"

hash_value = hashlib.sha256(data.encode()).hexdigest()

print(hash_value)
```

## 🔹 3. Password Hashing

**Password hashing** is the process of converting a password into a hash before storing it in a database.

Instead of storing the original password, applications store a password hash.

### How Password Hashing Works

1. User creates an account and enters a password.
2. The application generates a unique random salt.
3. The password and salt are processed using a password-hashing algorithm.
4. The resulting hash and salt are stored in the database.
5. During login, the application processes the entered password using the stored salt and the same algorithm.
6. The resulting hash is verified against the stored hash.

### Password Hashing Algorithms

| Algorithm | Purpose |
|---|---|
| Argon2id | Recommended modern password hashing |
| bcrypt | Password hashing |
| scrypt | Password hashing |
| PBKDF2 | Password-based key derivation |

> **Important:** Never use ordinary SHA-256 directly for password storage. It is too fast, making large-scale password guessing easier.

### What is Salt?

A **salt** is a random value added to a password before hashing.

**Why do we use salt?**

- Prevents identical passwords from having identical stored hashes when unique salts are used.
- Makes precomputed rainbow-table attacks ineffective.
- Makes attackers calculate hashes separately for each password.

## 🔹 4. Data Integrity

**Data integrity** means ensuring that data has not been modified, corrupted, or tampered with without authorization.

Hashing helps verify data integrity.

### Example: Alice and Bob

Suppose Alice sends a file to Bob.

1. Alice calculates the SHA-256 hash of the file.
2. Alice sends the file and its hash to Bob.
3. Bob calculates the SHA-256 hash of the received file.
4. Bob compares both hash values.
5. If they match, the file is consistent with the original data.

### Data Integrity Workflow

```text
          ALICE (SENDER)
                |
                v
          Original File
                |
                v
          SHA-256 Hash
                |
                v
       Sends File + Hash
                |
                v
          BOB (RECEIVER)
                |
                v
        Calculate New Hash
                |
                v
        Compare Both Hashes
                |
          +-----+-----+
          |           |
        Match       No Match
          |           |
          v           v
      Consistent    Modified
        Data          Data
```

> **Important:** A plain hash alone does not prove who sent the file. An attacker who can modify both the file and its hash could replace both. For authentication, use HMAC or a digital signature.

## 🔹 5. Hash Verification

**Hash verification** is the process of comparing hash values to check whether data has changed.

### Example Using Python

```python
import hashlib

def calculate_hash(filename):

    sha256 = hashlib.sha256()

    with open(filename, "rb") as file:

        for chunk in iter(lambda: file.read(4096), b""):
            sha256.update(chunk)

    return sha256.hexdigest()


original_hash = calculate_hash("original.txt")
received_hash = calculate_hash("received.txt")

if original_hash == received_hash:
    print("File integrity verified")
else:
    print("File has been modified")
```

### Understanding the Code

- `hashlib.sha256()` creates a SHA-256 hashing object.
- `open(filename, "rb")` reads the file in binary mode.
- `file.read(4096)` reads the file in chunks of 4096 bytes.
- `sha256.update()` processes each chunk.
- `hexdigest()` returns the hash as a hexadecimal string.
- Finally, both hashes are compared.

## 🔹 6. Collision Awareness

A **hash collision** occurs when two different inputs produce the same hash value.

### Example

```text
Input 1: Hello
Input 2: World

Hash 1: ABC123...
Hash 2: ABC123...
```

*This is an illustrative collision, not an actual SHA-256 example.*

### Why Do Collisions Happen?

Hash functions convert unlimited possible input values into a fixed-size output.

For example, SHA-256 produces a 256-bit hash.

There are:

\[
2^{256}
\]

possible SHA-256 outputs.

Since the input possibilities are unlimited but the output possibilities are finite, collisions must exist mathematically.

### Birthday Paradox

The birthday paradox explains why collisions can become likely much sooner than the total number of possible hash values might suggest.

For an ideal 256-bit hash, finding a collision using a generic birthday attack takes approximately:

\[
2^{128}
\]

hash operations.

### Collision-Resistant Algorithms

| Algorithm | Collision Resistance |
|---|---|
| MD5 | Broken |
| SHA-1 | Broken |
| SHA-256 | Currently considered secure |
| SHA-3 | Currently considered secure |

## 🔹 7. Real-World Applications

|---|---|
| Password Storage | Securely stores password verifiers |
| File Integrity | Detects unexpected file modifications |
| Digital Signatures | Hashes messages before signing |

| Malware Analysis | Identifies files using hash values |

## 🔹 8. Key Takeaways

- Hashing converts input data into a fixed-length output.
- A hash function is generally one-way.
- SHA-256 and SHA-3 are modern cryptographic hash algorithms.
- Password hashing should use Argon2id, bcrypt, scrypt, or PBKDF2.
- Salt protects password hashes against precomputed attacks.
- Hash verification helps detect data modifications.
- HMAC provides message authentication and integrity.
- A collision occurs when two different inputs produce the same hash.
- MD5 and SHA-1 should not be used where collision resistance is required.
