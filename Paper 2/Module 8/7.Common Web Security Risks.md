# 🛡️ 7. Understand Common Web Security Risks

> 🌐 **PAPER 2 · MODULE 4 · WEB FUNDAMENTALS**

Web security risks are vulnerabilities or weaknesses in web applications that attackers may exploit to access data, steal information, or disrupt application functionality.

Understanding these risks helps developers build secure web applications and cybersecurity professionals identify potential security weaknesses.

## 💉 1. Injection Attacks

**Injection attacks** occur when an application accepts untrusted user input and processes it as part of a command or query instead of treating it as ordinary data.

An attacker may manipulate input to make the application perform unintended operations.

### 🔹 Common Types

| Type | Description |
|---|---|
| SQL Injection (SQLi) | Manipulating database queries through malicious input. |
| Cross-Site Scripting (XSS) | Injecting malicious JavaScript into web pages. |
| Command Injection | Manipulating system commands through unsafe application input. |

### 💡 Example

Imagine a login form that accepts:
- Username
- Password

If the application does not properly validate and handle the input, an attacker may manipulate the database query.

### 🛡️ Prevention

- Input validation.
- Parameterized queries.
- Output encoding.
- Avoid executing untrusted input.

## 🔐 2. Broken Authentication

**Broken authentication** occurs when an application does not properly implement or manage user authentication.

Authentication is the process of verifying a user's identity.

### 🔹 Common Problems

- Weak password requirements.
- Poor session management.
- Missing multi-factor authentication (MFA).
- Improper password storage.
- Insecure password recovery mechanisms.

### 💡 Example

Imagine logging into an account on a website. If the website does not properly manage login sessions, someone else might gain unauthorized access to an account.

### 🛡️ Prevention

- Use strong password policies.
- Implement multi-factor authentication.
- Store passwords using secure hashing algorithms.
- Use secure session management.
- Implement account lockout or rate limiting where appropriate.

## 🔒 3. Sensitive Data Exposure

**Sensitive data exposure** occurs when an application fails to properly protect confidential information.

### 🔹 Examples of Sensitive Information

- Passwords.
- Credit card details.
- Personal information.
- Authentication tokens.
- API keys.

### 💡 Example

Imagine a website transmitting login credentials over an unencrypted HTTP connection. Someone monitoring the network may be able to read the transmitted information.

### 🛡️ Prevention

- Use HTTPS/TLS.
- Encrypt sensitive data where appropriate.
- Never store passwords as plain text.
- Avoid exposing API keys and secret credentials.
- Apply proper access controls.

## ⚙️ 4. Security Misconfigurations

**Security misconfiguration** occurs when a server, application, database, or security component is configured incorrectly or left with insecure default settings.

### 🔹 Common Examples

- Default usernames and passwords.
- Unnecessary services enabled.
- Debug mode enabled in production.
- Directory listing enabled.
- Unnecessary error details exposed.
- Outdated software and insecure configurations.

### 💡 Example

Imagine a developer deploys a website with debug mode enabled. The application might expose internal information through detailed error messages.

### 🛡️ Prevention

- Change default credentials.
- Disable unnecessary services.
- Disable debug mode in production.
- Apply security updates.
- Regularly review server configurations.

## 🌐 5. OWASP Awareness

**OWASP (Open Worldwide Application Security Project)** is a nonprofit organization that helps improve software and web application security.

OWASP provides security resources, guidelines, tools, and awareness materials for developers and cybersecurity professionals.

One of its most popular resources is the **OWASP Top 10**, which highlights major web application security risks.

### 📊 OWASP Top 10 (2025)

| Category | Meaning |
|---|---|
| 1. Broken Access Control | Users can access resources they shouldn't. |
| 2. Security Misconfiguration | Security settings are configured incorrectly. |
| 3. Software Supply Chain Failures | Risks from insecure software dependencies and development processes. |
| 4. Cryptographic Failures | Sensitive information is not properly protected. |
| 5. Injection | Untrusted input is interpreted as commands or queries. |
| 6. Insecure Design | Security is not properly considered during application design. |
| 7. Authentication Failures | Problems with verifying user identities. |
| 8. Software or Data Integrity Failures | Software or data cannot be trusted due to integrity issues. |
| 9. Security Logging and Alerting Failures | Security events are not properly recorded or monitored. |
| 10. Mishandling of Exceptional Conditions | Errors and unexpected situations are not handled securely. |
