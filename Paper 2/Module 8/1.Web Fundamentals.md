# 1. How Websites Work

A **website** is a collection of web pages and resources that users can access through a web browser using the internet.

### How does a website work?

When we enter a URL such as `https://www.google.com`, several processes happen behind the scenes.

### Steps involved

1. **URL Request:** User enters a website URL in the browser.
2. **DNS Resolution:** DNS converts the domain name into an IP address.
3. **Connection Establishment:** Browser establishes a connection with the server using TCP or QUIC.
4. **TLS Handshake:** For HTTPS, TLS establishes secure communication and authenticates the server.
5. **HTTP Request:** Browser sends an HTTP request to the server.
6. **Server Processing:** Server processes the request and communicates with the database if required.
7. **HTTP Response:** Server sends the requested information back.
8. **Rendering:** Browser processes HTML, CSS and JavaScript to display the webpage.

### Important terms

| Term | Meaning |
|---|---|
| URL | Address of a web resource |
| DNS | Converts domain names into IP addresses |
| HTTP | Protocol used for web communication |
| HTTPS | Secure HTTP communication using TLS |
| Browser | Software used to access websites |
| Web Server | Software that handles HTTP requests |

# 2. Client-Server Architecture

**Client-server architecture** is a computing model in which clients request services or resources, and servers provide them.

### Client

A client is a device or application that requests services from a server.

Examples:
- Google Chrome
- Firefox
- Mobile applications
- Desktop applications

### Server

A server is a computer or software that receives client requests, processes them and sends responses.

Examples:
- Web servers
- Database servers
- Application servers

### How client-server communication works

1. Client sends a request.
2. Server receives the request.
3. Server processes the request.
4. Server sends a response.
5. Client displays the received information.

### Client vs Server

| Client | Server |
|---|---|
| Sends requests | Receives requests |
| Requests resources | Provides resources |
| Receives responses | Sends responses |
| Usually user-facing | Provides services and processing |

### Common protocols

- HTTP – Web communication.
- HTTPS – Secure web communication.
- TCP – Reliable transport communication.
- DNS – Domain name resolution.

# 3. Frontend and Backend Concepts

Web applications generally have two major components: frontend and backend.

## 3.1 Frontend

Frontend is the user-facing part of a website that users interact with.

**Main technologies:**

| Technology | Purpose |
|---|---|
| HTML | Creates webpage structure |
| CSS | Controls webpage appearance |
| JavaScript | Adds functionality and interactivity |

Examples:
- Login forms
- Buttons
- Navigation menus
- Images and layouts

## 3.2 Backend

Backend is the server-side part of a web application that handles business logic, authentication, data processing and database communication.

**Common backend technologies:**

- Python (Django, Flask)
- JavaScript (Node.js)
- PHP
- Java
- C#

## 3.3 Database

A database stores and manages application information.

Examples:
- MySQL
- PostgreSQL
- MongoDB
- SQLite

### Frontend vs Backend

| Frontend | Backend |
|---|---|
| User-facing | Server-side processing |
| Runs mainly in browser | Runs on server |
| HTML, CSS, JavaScript | Python, PHP, Java, etc. |
| Displays information | Processes information |
| Handles user interactions | Handles business logic |

# 4. Web Application Workflows

A **web application workflow** describes how information moves between the user, frontend, backend and database.

### Example: User Login Workflow

1. User enters username and password.
2. Frontend collects the login information.
3. Frontend sends an HTTPS request to the backend.
4. Backend validates the submitted information.
5. Backend checks the user credentials against the database.
6. Database returns the relevant information.
7. Backend sends an appropriate response.
8. Frontend displays the result.

## Important Web Concepts

| Concept | Explanation |
|---|---|
| HTTP Request | Message sent by a client to a server |
| HTTP Response | Message returned by a server |
| API | Interface that allows applications to communicate |
| Authentication | Verifies the identity of a user |
| Authorization | Determines what an authenticated user can access |
| Session | Maintains user-related state across requests |
| Cookies | Small pieces of data stored by the browser |
| REST API | Architectural style for designing web APIs |

## HTTP Methods

HTTP methods define the type of action a client wants to perform on a server resource.

| Method | Purpose |
|---|---|
| GET | Retrieve information |
| POST | Submit information |
| PUT | Replace a resource |
| PATCH | Partially update a resource |
| DELETE | Delete a resource |

# 5. Modern Web Architecture

**Modern web architecture** describes how today's web applications are designed using multiple services, components and technologies.

## 5.1 Monolithic Architecture

- The entire application is developed as one unified application.
- Components are packaged and deployed together.
- Easier to start developing.
- Can become difficult to maintain as the application grows.

## 5.2 Microservices Architecture

- An application is divided into smaller independent services.
- Each service handles a specific responsibility.
- Services communicate through APIs or messaging systems.

**Example: E-commerce application**

- User management service.
- Payment service.
- Product service.
- Order service.

## 5.3 API Gateway

An API Gateway acts as an entry point for requests to backend services.

Functions:
- Routes requests to appropriate services.
- Can handle authentication.
- Can implement rate limiting.

## 5.4 Load Balancer

A load balancer distributes incoming requests across multiple servers.

Benefits:
- Improves performance.
- Prevents one server from receiving all requests.
- Improves availability.

## 5.5 CDN (Content Delivery Network)

A CDN is a distributed network of servers that delivers cached website content from locations closer to users.

Benefits:
- Faster content delivery.
- Reduced load on the main server.
- Improved website performance.

## 5.6 Cloud Computing

Cloud computing provides computing resources, storage and networking through cloud platforms.

Examples:
- AWS
- Microsoft Azure
- Google Cloud

### Modern Architecture Comparison

| Architecture | Main Idea |
|---|---|
| Monolithic | One unified application |
| Microservices | Multiple independent services |
| Serverless | Cloud provider manages server infrastructure |
| Three-tier | Presentation, application and data layers |

# 6. Cybersecurity Perspective

Understanding web fundamentals is important in cybersecurity because every component of a web application can introduce security risks.

### Common Web Vulnerabilities

| Component | Security Risk |
|---|---|
| Frontend | Cross-Site Scripting (XSS) |
| Backend | Injection vulnerabilities |
| Database | SQL Injection, data exposure |
| API | Broken Access Control |
| Communication | Man-in-the-Middle attacks |
| Session Management | Session hijacking |
| Configuration | Security misconfiguration |

### Important Security Mechanisms

| Mechanism | Purpose |
|---|---|
| HTTPS/TLS | Protects communication |
| Input Validation | Checks user-provided data |
| Authentication | Verifies user identity |
| Authorization | Controls access |
| Secure Cookies | Protects session-related data |
| Security Headers | Adds browser-side security protections |
