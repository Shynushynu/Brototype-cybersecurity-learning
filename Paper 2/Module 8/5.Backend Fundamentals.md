## 1. 🔗 APIs (Application Programming Interfaces)

An **API** is a mechanism that allows two software applications to communicate with each other.

In web development, APIs commonly allow the frontend to communicate with the backend.

### ⚙️ How Does an API Work?

Imagine you are logging in to Facebook.

```text
       FRONTEND (Browser)
               |
               |
        API REQUEST
               |
               ▼
        BACKEND (Server)
               |
               |
         DATABASE
               |
               ▼
        API RESPONSE
               |
               ▼
       FRONTEND (Browser)
```

### 📌 Important API Concepts

| Concept | Meaning |
|---|---|
| API Endpoint | A specific URL where an API can be accessed |
| Request | Data sent to an API |
| Response | Data returned by an API |
| JSON | Common format for exchanging data |
| HTTP Methods | GET, POST, PUT, PATCH, DELETE |
| Status Codes | Indicate the result of an HTTP request |

**Example:**

```http
GET /api/users
```

The server might respond:

```json
{
    "id": 101,
    "name": "Shynu",
    "role": "student"
}
```

> 💡 **Remember**
> - API is not a server.
> - API is not a database.
> - API provides a way for applications to communicate.

## 2. 🗄️ Databases

A **database** is an organized collection of information that can be stored, retrieved, updated, and managed.

Web applications use databases to store information such as:

- 👤 User accounts
- 🔑 Password hashes
- 📝 Profile information
- 🛒 Products and orders
- 💬 Messages

### 📂 Types of Databases

There are two major categories.

### A. SQL Databases (Relational)

SQL databases store information in tables consisting of rows and columns.

**Examples:**
- MySQL
- PostgreSQL
- SQLite

**Example Table:**

| ID | Username | Email |
|---|---|---|
| 1 | Shynu | shynu@example.com |
| 2 | Alex | alex@example.com |

### B. NoSQL Databases (Non-relational)

NoSQL databases support different ways of storing data, including document-based structures.

**Examples:**
- MongoDB
- Redis

**Example Document:**

```json
{
    "username": "Shynu",
    "email": "shynu@example.com",
    "skills": ["Python", "HTML", "CSS"]
}
```

### ⚖️ SQL vs NoSQL

| SQL | NoSQL |
|---|---|
| Tables | Different data structures |
| Rows and columns | Documents, key-value, etc. |
| Often uses fixed schemas | Often supports flexible schemas |
| MySQL, PostgreSQL | MongoDB, Redis |

> 🛡️ **Cybersecurity Connection**
>
> Database security involves protecting stored information from unauthorized access, SQL injection, data leakage, and data manipulation.

## 3. 🔐 Authentication Concepts

**Authentication** is the process of verifying the identity of a user.

In simple words:

### WHO ARE YOU?

Authentication verifies your identity.

For example, when you log in to Facebook using your email and password, the application checks whether your credentials are valid.

### 📌 Important Concepts

| Concept | Explanation |
|---|---|
| Authentication | Verifying user identity |
| Authorization | Determining what a user can access |
| Credentials | Username, password, etc. |
| MFA | Multiple authentication factors |
| Password Hashing | Securely storing password representations |
| OAuth | Framework for delegated access |

### ⚔️ Authentication vs Authorization

Imagine a student logging into a college portal.

- **Authentication:** Is this person a valid student?
- **Authorization:** Is this student allowed to access the admin dashboard?

| Authentication | Authorization |
|---|---|
| Verifies identity | Checks permissions |
| WHO ARE YOU? | WHAT CAN YOU ACCESS? |
| Login verification | Access control |

### 🔑 Password Hashing

Web applications should not store users' original passwords directly.

Instead, they use password-hashing algorithms such as:

- Argon2
- bcrypt
- scrypt

When a user logs in, the application verifies the entered password against the stored password hash.

## 4. 🍪 Session Management

**Session management** is the process of maintaining a user's state and identity across multiple requests.

### 🤔 Why Do We Need Sessions?

HTTP is a **stateless protocol**.

This means the server does not automatically remember previous requests.

For example:

1. You log in to Facebook.
2. You open your profile.
3. You visit your messages.
4. You open notifications.

Without a mechanism to maintain your login state, the server would need to authenticate you again for every request.

Session management solves this problem.

### ⚙️ How Does Session Management Work?

1. User submits login credentials.
2. Server verifies the credentials.
3. Server creates a session.
4. Server sends a session identifier to the browser, commonly through a cookie.
5. Browser sends that cookie with subsequent requests.
6. Server uses the session identifier to recognize the user.

### 📌 Important Terms

| Term | Meaning |
|---|---|
| Session | Information representing a user's interaction |
| Cookie | Small data stored in the browser |
| Session ID | Identifier used to associate requests with a session |
| JWT | JSON Web Token, commonly used for stateless authentication |
| Session Expiry | Time after which a session becomes invalid |
| Logout | Ends the authenticated session |

> ⚠️ **Cybersecurity Connection**
>
> Important session-related security concerns:
> - Session Hijacking
> - Session Fixation
> - Insecure Cookie Configurations

## 5. 🔄 Web Application Workflows

A **web application workflow** describes how information moves between the frontend, backend, database, and other services to complete a task.

Let's understand it using a registration page.

### 📝 Example: Creating an Account

```text
       USER INPUT
            |
            ▼
         FRONTEND
       (HTML + JS)
            |
            ▼
       API REQUEST
            |
            ▼
         BACKEND
      (Validation)
            |
            ▼
         DATABASE
      (Store Data)
            |
            ▼
       API RESPONSE
            |
            ▼
         FRONTEND
      (Display Result)
```

### 📌 Step-by-Step Explanation

1. **User Input:** User enters their name, email, and password.
2. **Frontend:** HTML and JavaScript collect the information.
3. **API Request:** Frontend sends the information to the backend.
4. **Backend Processing:** Server validates the submitted information.
5. **Database:** Server stores the user information, including a securely generated password hash.
6. **API Response:** Server returns a success or error response.
7. **Frontend:** Browser displays the result to the user.

### 📌 Common Web Application Workflows

| Workflow | Description |
|---|---|
| Registration | Creating a new user account |
| Login | Verifying user credentials |
| Data Retrieval | Fetching information from a database |
| Data Submission | Sending information to the server |
| File Upload | Uploading files to a server |
| Logout | Ending the authenticated session |
